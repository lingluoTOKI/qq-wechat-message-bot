## 三、Core 发现：两种请求形态在交替

`attribution` 暴露两种稳定形态：

| 形态 | system | tools | 推测来源 |
|---|---|---|---|
| **A** | 2,256 | 2,595 | 从 `cmd_config` 读 persona（**无 tools/skills 字段**）→ 退化为「全量工具 + 全部技能」 |
| **B** | 1,624 | 1,395 | 从 DB 读完整人格 → 8 工具白名单 |

差值：system −632（=Skills 块）、tools −1,200（=多出的工具）。

**根因**（`astr_main_agent.py:628` / `:632`）：

```python
if persona and persona.get("skills") is not None:
    if not persona["skills"]:
        skills = []          # 显式空列表 → 不注入
    # 若 persona 无 skills 字段 → 注入全部内置技能

if (persona and persona.get("tools") is None) or not persona:
    persona_toolset = tmgr.get_full_tool_set()   # → 全量工具
```

`cmd_config.json` 里的 `agent_runner.config.persona` 只有
`{persona_id, safety_mode, safety_mode_strategy}`，**没有 tools / skills 键**，
所以那条路径必然退化成形态 A。

## 四、已落地的修复

### 1. 彻底停止 Skills 注入（省 632 token/请求）

两道保险：

- **人格表**：`personas.skills` 从 `"null"` 改为 `"[]"`（3 个人格全部）
  - 脚本：`scripts/clear_persona_skills.py`
  - 备份：`data_v4.db.bak-skills-<时间戳>`
- **目录层**（关键）：把 4 个内置技能移出 skills 根目录
  - `astrbot/builtin_stars/astrbot/skills/` → `/AstrBot/data/_disabled_skills/`
  - 移走：`documents` `pdf` `skill-creator` `spreadsheets`
  - 脚本：`scripts/disable_builtin_skills.py`
  - 验证：`list_skills(runtime=none/local)` 均返回 **0 个**
  - **无需重启**（SkillManager 每请求新建）

**为什么必须做目录层**：人格表只能覆盖形态 B；形态 A 根本不读人格表的 skills，
只有让 `list_skills()` 返回空表才能两条路径都断掉。

**为什么零功能损失**：框架在该块末尾自己写着
「User has not enabled the Computer Use feature. You cannot use skills.」
——技能本来就执行不了。

### 2. 诊断探针（临时）

`astrbot_plugin_cacheprobe`（`scripts/cacheprobe/`）
在 `on_llm_request` 记录每次请求的：`kind(PERSONA/NOPERSONA)`、`sp_len`、
是否有 skills、tool 数、**调用栈回溯**。用于最终确认形态 A 的具体调用方。

诊断完成后应删除该插件（每请求多一行日志）。

### 关于 extra 的关键更正

原以为 `extra`（877~1,930 token）来自记忆碎片，**实测不成立**：

| 表 | 条数 | 平均 | top3 最坏 |
|---|---|---|---|
| `memory_atoms`（碎片） | 20 | 26 token | 102 |
| **`documents`（每日群聊日记）** | 26 | **402 token** | **1,842** |

`top_k=3` 召回的是 `documents`——每天 700~900 字的叙事日记。
配置里**没有单条注入长度上限**，只能靠 `top_k` 控制。
