# AstrBot 表达风格插件代码审查报告

## 审查范围
- **插件版本**: AstrBot 4.29.3
- **核心功能**: 从情景记忆提取群内表达风格，人工审批后注入
- **当前状态**: `enabled=true`, `inject_enabled=false`, 仅DeepSeek模型允许学习
- **审查重点**: 并发安全、预算控制、数据一致性、注入时序

## 已确认缺陷与条件风险

### P1: 预算门在并发学习任务中的竞态条件
**文件**: `main.py`  
**行号**: 182-209  
**触发条件**: 同一小时内多个群同时触发学习任务  
**影响**: 
- 多个学习任务可能同时调用 `scope(origin)`，导致预算计算错误
- `scope` 是 `ContextVar`，在异步任务中可能被意外覆盖
- 预算超支风险：多个群共享同一预算时，可能超出 `group_daily_budget_cny`

**最小修改建议**:
```python
async def _learn_group(self, group_id: str) -> dict:
    async with self._learning_lock:  # 已有锁，但需确保 scope 在锁内
        self._reload_cfg()
        if not self.cfg.get("enabled") or not self._group_allowed(group_id):
            return {"advanced": False, "error": "disabled_or_scope"}
        # ... 原有逻辑 ...
        with scope(origin):  # 确保在锁内
            return await self._learn_group_impl(group_id)
```

### P2: 学习游标在预算中断时未回滚
**文件**: `main.py`  
**行号**: 206-208  
**触发条件**: 学习过程中预算耗尽  
**影响**:
- 游标已推进但学习失败，导致重复处理相同消息
- 可能触发无限循环学习（每次都因预算失败）

**最小修改建议**:
```python
# 在 _learn_group_impl 中捕获预算异常后回滚游标
try:
    result = await _learning.process_group(...)
except ModelBudgetBlocked:
    logger.info("[dafeiyu_style] 预算已用完，回滚游标：%s" % group_id)
    self.store.set_meta("cursor:%s" % group_id, cursor)  # 回滚游标
    return {"advanced": False, "error": "budget"}
```

### P2: 跨群数据隔离缺失
**文件**: `learning.py`  
**行号**: 22-55  
**触发条件**: 配置中 `groups=[]` 时处理所有群  
**影响**:
- `read_events` 未按群隔离游标，可能导致群间数据混淆
- `process_group` 中 `since_id` 是全局游标，而非群级游标

**证据不足**: 源码中 `store.get_meta("cursor:" + group_id)` 已实现群级游标，但 `read_events` 未使用该游标（第196行直接传 `since_id`）。

**最小修改建议**:
```python
# 在 _learn_group 中使用群级游标
cursor = int(self.store.get_meta("cursor:" + group_id, "0"))
rows, _ = await asyncio.to_thread(_learning.read_events, self.memory_db, cursor,
    [group_id], int(self.cfg["min_msg_len"]), int(self.cfg["max_msg_len"]),
    int(self.cfg["max_batch"]))
```

### P2: SQLite锁超时可能导致学习任务阻塞
**文件**: `store.py`  
**行号**: 61  
**触发条件**: 高并发写入时  
**影响**:
- `timeout=0.02` 可能导致频繁锁等待

self.db = sqlite3.connect(path, timeout=5.0)  # 增加超时时间

### P3: 热关闭时未清理未完成的任务
**文件**: `main.py`  
**行号**: 150-156  
**触发条件**: 插件被卸载时  
**影响**:
- 未完成的 `_learn_group` 任务可能继续运行
- 可能导致数据库锁未释放

**最小修改建议**:
```python
async def terminate(self):
    if self._task:
        self._task.cancel()
        try:
            await self._task
        except (asyncio.CancelledError, Exception):
            pass
    # 等待所有学习任务完成
    async with self._learning_lock:
        pass
    self.store.close()
```

### P3: 配置热加载时可能读取到不一致状态
**文件**: `main.py`  
**行号**: 128-136  
**触发条件**: 配置文件被外部修改  
**影响**:
- `_reload_cfg` 读取新配置但未同步到正在运行的任务
- 可能导致学习任务使用错误的 `groups` 或 `hour`

**最小修改建议**:
```python
def _reload_cfg(self):
    try:
        mtime = os.path.getmtime(self.config_path)
    except OSError:
        return
    if mtime > self._cfg_mtime:
        new_cfg = _config.load_config(self.config_path)
        # 检查关键配置变化
        if new_cfg.get("enabled") != self.cfg.get("enabled"):
            logger.warning("[dafeiyu_style] enabled 配置变更，需重启任务")
        self.cfg = new_cfg
        self.memory_db = self._resolve_memory_db()
        self._cfg_mtime = mtime
```

## 最需要补的5个验证用例

1. **并发学习任务预算隔离测试**
   - 场景：同时学习3个群，每个群预算0.5元
   - 验证：总预算不超过1.5元，无群预算超支

2. **预算中断游标回滚测试**
   - 场景：学习过程中预算耗尽
   - 验证：游标回滚到中断点，不重复处理消息

3. **跨群数据隔离测试**
   - 场景：配置 `groups=[]`，学习群A和B
   - 验证：群A和B的游标独立，数据不混淆

4. **SQLite锁超时恢复测试**
   - 场景：高并发写入时锁超时
   - 验证：任务不阻塞，最终成功或正确失败

5. **热关闭任务清理测试**
   - 场景：插件卸载时正在学习
   - 验证：所有任务取消，数据库锁释放

## 是否适合保持当前"学习开启、注入关闭"状态

**判断：适合，但需补充以下验证**

**理由**:
1. **学习阶段风险可控**：
   - `inject_enabled=false` 避免了注入时的预算冲突
   - 人工审批机制确保数据质量
   - DeepSeek模型限制降低了误用风险

2. **需补充的验证**：
   - 并发学习任务的预算隔离（P1）
   - 预算中断时的游标回滚（P2）
   - 跨群数据隔离（P2）

3. **建议**：
   - 在进入注入阶段前，确保上述P1/P2问题已修复
   - 增加真实环境下的24小时资源及首轮学习验收测试

**结论**：当前状态可安全运行，但需完成上述验证后才能启用注入功能。
