# 当前插件使用方案与验收标准

> 更新：下文保留第一批基线；后续已完成与仍待复测的项目以[第二轮验收记录](第二轮验收记录.md)为准。记忆按用户选择保持全局共享，只增加来源标签。


适用：2026-10-29本轮更新后的部署。已上线内容和未测边界见[实施记录](实施与回滚记录.md)。

## 推荐入口

| 要做的事 | 推荐输入 | 预期 |
|---|---|---|
| 查看全部功能 | `/功能`、`/帮助` | 中文说明书；英文`/help`保留给框架内置帮助 |
| 查费用 | `/用量`、`/用量 7` | 北京时间窗口，成本库费用，未知费用明确标注 |
| 查服务器 | `/服务器状态`、`/在线玩家 契约服` | 区分状态摘要与在线明细；查询失败不编造 |
| 查榜 | `/排行榜`、`/单人榜`、`/排行榜 单人 TOKI` | 累计积分、接口日期和查询时间；保留并列与同名记录 |
| 聊天查榜 | @机器人并明确游戏昵称和单人/多人 | 现有人格的query_project_info可传昵称与分榜，不根据QQ昵称推断游戏身份 |
| 上报问题 | `/报bug 主服进入战斗后黑屏` | 返回编号；后续通过编号查进度 |
| 翻唱音频 | `/翻唱`后由本人发送音频 | 不接走同群其他人的音频；完整推理和产物需后续实测 |
| 听原唱 | `/搜索歌曲 关键词` | 按该搜索的候选回复；避免同时开启另一套选歌等待 |
| 查记忆 | `/记忆 状态`、明确人物或关键词追问 | 能追溯的结果带时间；没有证据时说明缺失 |
| B站订阅 | `/bili 状态`、`/bili 订阅 UID` | 使用独立动态订阅入口；另一Bilibili监听无凭据时暂停 |

`/功能 群管`会提示守护者插件当前未启用；本次没有开启禁言、踢人等管理能力。语音、翻唱、聊天和部分记忆任务可能调用外部付费服务，不能以说明书本身不调用模型推断所有功能免费。

## 连贯操作约定

- 查榜时提供游戏昵称；同名记录保留，不擅自合并成一个人。
- 同轮相同状态/排行榜工具查询共享已完成结果，不复用到其他用户事件；后续新消息重新查询。
- 同时需要原唱与翻唱时分别完成一条链路，当前尚未统一多插件纯数字选择仲裁。
- 主动播报以平台返回消息id为成功；失败不会立即换第二条路径重发。日晨报最多3次间隔重试，已经成功的目标不重复发送。
- 生日倒计时按真实日历；2月29日按下一次真实闰日计算。按目标记录回执，部分目标失败不会把全部目标记成完成。
- 自动记忆注入去重、按得分排序并控制长度；不删除旧记忆，也没有更改全局共享范围。私聊来源边界仍需后续明确和验证。

## 用户验收

先验证不调用付费服务的命令：`/功能`、`/用量`、`/排行榜 单人 昵称`、`/服务器状态`。核对事实值、数据时间、失败提示和是否出现多余回复；不能仅用“机器人有回复”作为通过。

管理员本人再验证`/ctxbudget`是否响应。群推送、生日推送、付费模型、语音和翻唱应指定目标与样本后单独安排，不在日常群无计划重复触发。管理功能用隔离环境，不在真实成员上试踢人禁言。

完整可复现标准见[功能验证矩阵](功能验证矩阵.md)：记录输入、版本、配置差异、北京时间、源数据、实际输出及回执；确定性用例可重复执行3次。性能需要同类别、同条件样本，每类不足30条仅记录观察值。

发现费用异常先核对币种和统计窗口；发现未送达先核对平台是否就绪、权限和回执；不要直接提高预算或重启游戏服来掩盖问题。每次只调整一个可归因批次。
