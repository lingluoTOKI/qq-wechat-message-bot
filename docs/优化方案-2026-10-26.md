## 二、已发现并修复的 5 个问题

### 🔴 1. 语音功能 100% 失效 —— `edge-tts` 未声明依赖，重启即丢

**现象**
```
[ERRO] [tts_api.dy_tts_api:40]: Edge TTS 合成失败: No module named 'edge_tts'
[WARN] [astrbot_plugin_clonetts.main:171]: 语音合成返回空数据，跳过本次语音回复
```
凌晨 00:50-00:51 连挂 3 次。

**根因**：`clonetts/requirements.txt` 只声明了 `aiohttp / pydantic / pydub / ffmpeg`，
**没有 `edge-tts`**。之前能用是容器内手装的，昨晚 21:58 重启后蒸发。
→ 这正是昨晚那类"重启即丢"的定时炸弹，只是这次炸在语音上。

**修复（双保险）**
1. `pip install --target /AstrBot/data/pylibs --no-deps edge-tts` → 落在**持久卷**，`PYTHONPATH` 已指向它，重建容器也不丢
2. `requirements.txt` 追加 `edge-tts` → AstrBot 启动时的 `pip_installer` 会自动装

**验证**：重启后实测合成 12,816 字节音频 ✅

### 🔴 2. 框架 bug：预算超限时 agent 直接崩溃

**现象**
```
[WARN] [runners.tool_loop_agent_runner:547]: Skipping LLM request because no...
[ERRO] [core.astr_agent_run_util:327]: Traceback (most recent call last):
  File "/AstrBot/astrbot/core/agent/runners/tool_loop_agent_runner.py", line 875, in step
    self.stats.current_context_tokens = 0
AttributeError: 'ToolLoopAgentRunner' object has no attribute 'stats'
→ 用户收到 "Error occurred during AI execution. Error Type: AttributeError"
```

**根因**：`self.stats = AgentStats()` **只在 `reset()` 方法末尾（331 行）初始化**；
而当 LLM 请求被跳过（预算超限，547 行）时，执行流直接走到 875 行访问 `self.stats`，
此时属性尚不存在 → AttributeError → 整个 agent 崩溃。

**这是 AstrBot v4.29.3 上游 bug**，不是我们的插件引起的。但**我们把限额调小之后更容易触发**
（限额越低，越早进入"跳过"路径）。

**修复**：在 875 行前插入防御性初始化（纯兜底，不改动任何其他逻辑）
```python
# [patch] stats-not-initialized
if not hasattr(self, 'stats'):
    self.stats = AgentStats()
    self.stats.start_time = time.time()
```

**落地方式（关键）**：改容器内文件会在重建时丢失，因此
- 补丁脚本持久化到 `/AstrBot/data/patch/patch_astrbot_stats.py`
- compose 加 `post_start` 钩子自动应用（Docker Compose 2.40.3 支持，需 ≥2.30）
- **已实测**：容器重建后补丁标记仍为 1 处 ✅

### 🟢 5. pip 源太慢，拖慢每次启动

**现象**：AstrBot 启动时逐插件跑 `pip install -r requirements.txt`，
从 PyPI 官方源拉 `opencv` 61MB **直接超时失败**（后台任务静默失败）。

**对比**：换阿里云镜像 `https://mirrors.aliyun.com/pypi/simple/` → **1 分钟装完**。

**修复**：compose 的 `environment` 加
```yaml
- PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/
- PIP_TRUSTED_HOST=mirrors.aliyun.com
```
启动耗时从 ~110s 降到 **87s**。

## 三、这次复盘沉淀的方法

### 「重启即丢」依赖的完整审计法
`audit_plugin_deps.py` → `check_imports.py` 两步：
1. 扫所有插件 `requirements.txt` 的包名，对每个跑 `pip show`
2. 再用 `import` 逐个验证（**包名≠import 名时 pip show 会误报**）

**踩过的坑**：`pip show` 说 `networkx` 缺失，但真因是它当时确实没装；
而 `opencv-python-headless` 的 import 名是 `cv2`、`pytz`/`tomli` 也有别名 —— 必须用 import 复核。

### 容器内临时文件会随重建消失
`/tmp/tuv.py` 等测试脚本在 `docker compose up -d` 重建后全部消失（`/tmp` 不在挂载卷里）。
持久卷 `/AstrBot/data/` 下的才活下来。

### 成本库 `created_at` 存的是 UTC
按小时看用量时要用 `strftime('%H', created_at)` 读到的其实是 UTC 小时，
换算北京时间要 +8。今日凌晨 0-8 点（UTC 16:00-24:00）有 37 次调用。
